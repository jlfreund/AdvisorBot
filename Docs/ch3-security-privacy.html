Chapter 3 Security & Privacy

Security & Privacy Architecture

Defense-in-depth protection: localhost binding, persistent 0600 session secrets, server-enforced Privacy Shield profiles, and offline AI execution.

Personal financial data requires rigorous confidentiality guarantees. AdvisorBot implements a defense-in-depth security model designed specifically for local execution.

3.1 Localhost & Network Isolation

AdvisorBot is strictly local software:

  • Strict 127.0.0.1 Binding: The local web server binds strictly to the loopback interface (127.0.0.1) and refuses external LAN connections.
  • Zero Cloud Telemetry & Sidecar-Only Quotes: No analytics scripts, tracking beacons, or third-party fonts are bundled. Live stock quotes are fetched solely through the local server proxy (GET /api/quote)—never via third-party browser CORS proxies.
  • Owner-Only Local Storage & Dynamic Aliasing: Portfolio SQLite databases and configuration files are restricted to owner-only permissions (0600) and display your real account names and contract numbers in Live View—automatically aliasing them to realistic personas in Demo Mode and translating them to ACCT_N / CONTRACT_N tokens when AI Chat Privacy Shield obfuscation (Mode B or C) is enabled, while exported view-models trim investor/beneficiary birthdates to YYYY-MM.
  • Git Hygiene & Sensitive File Exclusions: The repository ships without portfolio data, and .gitignore excludes private portfolio folders, API credentials, session tokens, and generated HTML snapshots so personal records and keys are never committed to Git.

3.2 Protection From Browser Inspection, Cross-Tab & Local Loopback Attacks

AdvisorBot isolates advisorbot_server.py at http://127.0.0.1:8765 using same-origin serving, Host/Origin/CSRF validation, and persistent local session secrets:

🛡️ Same-Origin Serving & Zero CORS Exposure

The dashboard is served strictly same-origin directly from the local server (http://127.0.0.1:8765/). All Access-Control-Allow-* CORS headers and Chrome's Access-Control-Allow-Private-Network header are completely omitted, and mutating POST/DELETE routes enforce same-port Origin, Sec-Fetch-Site, and JSON/X-Requested-With CSRF checks.

🔑 Persistent 0600 Secret & 1-Year Strict Cookies

A 256-bit machine-local secret persisted in Data/.session_secret (mode 0600, mirrored at runtime to Data/.session_token for local CLI tools and unlinked on shutdown) gates the dashboard (/ and /index.html), every API endpoint, statement files, documentation, and scenario snapshots via a 1-year SameSite=Strict HttpOnly cookie (bootstrapped once via /?token=… across both 127.0.0.1 and localhost) or X-Session-Token header. Only /api/health, /favicon.ico, and top-level repository docs (README.md, DISCLAIMER.md, LICENSE, NOTICE) are unauthenticated.

🌐 Loopback Host & DNS Rebinding Defense

Every incoming request validates both the HTTP Host header and port against the bound loopback listener (127.0.0.1 or localhost), preventing DNS rebinding attacks where an external malicious domain resolves to the local port.

🔒 Sandboxed Execution & No Ambient CLI Privileges

The server executes with standard user permissions, invokes subprocesses solely via explicit argv lists without shell=True, and disables permission-bypass flags and slash commands on optional headless CLI calls.

If a saved privacy policy is unreadable or contains an unsupported mode, private dashboard requests and AI calls stop until the portfolio’s privacy_registry.json is restored. After switching households or Demo Mode, reopen the dashboard if a stale tab reports that its portfolio changed.

Why the "Session Authentication Required" Screen Exists & When It Is Needed

If you visit http://127.0.0.1:8765/ in a browser that does not yet carry an AdvisorBot session cookie, the server returns a Session Authentication Required screen instructing you to run advisorbot_server.py --open rather than automatically logging the browser in.

Threat Boundary Behind the One-Time Bootstrap:
  • Trusted workstation. The session secret protects requests from callers without a credential. Browser cookies are shared across ports on the same hostname. Use AdvisorBot where the local web services your browser visits are trusted.
  • Why normal restarts do NOT prompt you again: Unlike ephemeral per-process tokens, Data/.session_secret persists across server restarts and pairs with a 1-year HttpOnly; SameSite=Strict cookie. Open browser tabs and bookmarks reconnect seamlessly whenever advisorbot_server.py stops and restarts.
  • When you will see the screen:
    1. Opening AdvisorBot for the first time in a new browser, browser profile, or Private/Incognito window.
    2. Switching hostnames between http://127.0.0.1:8765/ and http://localhost:8765/ (browsers maintain separate cookie jars for 127.0.0.1 vs. localhost—bookmarking http://127.0.0.1:8765/ avoids hostname mismatches).
    3. After clearing browser cookies or explicitly revoking sessions via advisorbot_server.py --rotate-token.
  • Browser sign-in. Run python3 Scripts/advisorbot_server.py --open to open the dashboard, including when this checkout’s server is already running. The launcher verifies the instance before opening the browser. If another application owns the port, choose a different port.
  • What to bookmark. Bookmark the dashboard after sign-in. A launcher link works once and remains available until used or until that server stops. The browser stores the signed cookie automatically and reconnects across ordinary restarts. An older valid cookie is upgraded automatically on a private request. If a new profile or cleared cookies require sign-in, run --open again in the same browser profile. Leave any tab with unsaved edits open and retry Save there.

3.3 The 3 AI Privacy Profiles

When using the in-page AI Financial Assistant or MCP tools, AdvisorBot translates tool inputs and outputs according to the active Privacy Shield mode (Mode B performs reversible, session-stable pseudonymisation — real names, accounts, institutions, and primary employer symbols are aliased, while exact dollar figures and year-month birthdates remain unscaled for accurate tax/RMD modeling):

Legend: Clear Text (Green) — real unmasked data sent Obfuscated / Perturbed (Yellow) — synthetic aliases or scaled values
Profile Names & Institutions Dollar Amounts Dates & Birthdays Recommended Use Case
Mode A: Clear Text Real names & tickers Exact dollar values Exact birthdates Local offline LLMs (Ollama) or trusted internal models.
Mode B: Obfuscated Names (Pseudonymised) Reversible session-stable aliases (e.g. "Apex Corp", "PRIMARY_EQ") Exact dollar values Year-month birthdates (YYYY-MM, day masked) Cloud models when exact tax-bracket and RMD math is required while masking family/account/employer identifiers. Note: exact dollar magnitudes remain visible.
Mode C: Obfuscated Names & Values Synthetic aliases Multiplied by your configured deterministic Portfolio Value Scale Factor (e.g. 0.35x) Shifted birth years (configurable ±N yr offset; day masked to YYYY-MM) Maximum privacy with external cloud AI. Protects exact net worth, birth years, and family identities.
⚠️ Warning: AI Chat cannot reason accurately about dollar-threshold tax questions or exact RMD / Social Security start years in this mode, because progressive tax brackets, NIIT thresholds, Social Security provisional-income tiers, and age-based milestones depend on unscaled dollar magnitudes and unshifted birth years.

3.4 100% Offline Local LLMs (Ollama & LM Studio)

For complete privacy, you can run open-weights models on your own computer across macOS, Linux, and Windows. AdvisorBot natively supports any OpenAI-compatible local server:

macOS Terminal (zsh / bash) 
# 1. Install (if needed) & start Ollama with your preferred model
brew install ollama
ollama run llama3.1

# 2. Configure AdvisorBot from the repo root
mkdir -p Data/Config/LLM
cp Examples/llm_config.local_ollama.json Data/Config/LLM/ollama.json

# 3. Open Settings > Privacy & AI Security and select your local Ollama model.
Linux Terminal (bash / zsh) 
# 1. Install (if needed) & start Ollama with your preferred model
curl -fsSL https://ollama.com/install.sh | sh
ollama run llama3.1

# 2. Configure AdvisorBot from the repo root
mkdir -p Data/Config/LLM
cp Examples/llm_config.local_ollama.json Data/Config/LLM/ollama.json

# 3. Open Settings > Privacy & AI Security and select your local Ollama model.
Windows PowerShell 
# 1. Install (if needed) & start Ollama with your preferred model
winget install Ollama.Ollama
ollama run llama3.1

# 2. Configure AdvisorBot from the repo root
New-Item -ItemType Directory -Force -Path Data\Config\LLM | Out-Null
Copy-Item Examples\llm_config.local_ollama.json Data\Config\LLM\ollama.json

# 3. Open Settings > Privacy & AI Security and select your local Ollama model.

3.5 Maintaining the Alias & Synonym Table

The Alias & Synonym Registry is a unified substitution dictionary used to replace real identifying names and their common synonyms with realistic, synthetic pseudonyms. Crucially, this table is shared by both AI Chat Obfuscation (Modes B & C) and Demo Mode. In AI Chat, aliases ensure cloud models never see real personal names or account identifiers; in Demo Mode, the same aliases are rendered directly across the on-screen dashboard and tables for privacy-safe screen shares and presentations.

Algorithmic Generation & Entity Seed Pools

When a portfolio is initialized or updated, AdvisorBot automatically populates the table using a deterministic pseudonymization algorithm:

  • Entity Extraction & Synonym Mapping: The ingestion engine extracts every primary entity from your portfolio (investors, beneficiaries, employers, stock tickers, financial institutions, insurance carriers, and account numbers) and pairs each with its common variations and synonyms (e.g., "Morgan Stanley", "MS", and "Morgan Stanley & Co." all map to the same alias).
  • Domain-Aware Synthetic Pools: Each real entity is categorized by type and paired with a realistic replacement drawn deterministically from large, curated synthetic pools (including 20 bank institutions, 200 synthetic equities with realistic tickers, 25 mutual funds, 12 asset managers, and 10 insurance carriers).
  • Deterministic Stable Seeding: Assignments are calculated using a stable hash seed. An entity always receives the exact same synthetic alias across repeated runs and server restarts, preserving coherent financial narratives without random drift.

Inspecting & Editing the Registry

Located under Settings > Privacy & AI Security > Alias & Synonym Registry, this interactive collapsible panel allows you to inspect every active alias pair:

  • Bidirectional Translation: When the AI Assistant answers, the client-side UI translates the aliases back into real names in the live chat transcript so you read natural responses.
  • Manual Customization: You can directly edit any alias or synonym in the table. User customizations are persisted to your portfolio's local configuration, taking precedence over default algorithmic assignments.

3.6 Unsupported Banks & Statement Parser Privacy

Constructing your portfolio from statements issued by unsupported banks or financial institutions will require the development of new Python script parsers to ingest those statements into your portfolio SQLite database. Unless you want to write those parser scripts by hand from scratch, you will need to share your bank statements with an AI coding agent (such as Claude, Gemini, Antigravity, or Cursor) so the agent can study the visual formatting, table layouts, and text streams of the document and develop a new Python parser plugin to ingest the file into the application database.

While the resulting parser plugin runs 100% locally on your machine once generated, sharing raw statements with an external cloud AI agent during the development phase exposes the financial records, transaction histories, and identifiers contained in those files. To help reduce this privacy exposure across the community over time, users are encouraged to share their sanitized, generic parser scripts in the project's Git repository. As community contributions expand the library of built-in institution parsers, future users will be able to ingest their statements out-of-the-box without ever needing to expose their private financial documents to an AI agent to build custom parsers.

🔒 Best Practices When Collaborating With AI on Parsers:
  • Redact Sensitive PII First: Before sharing an unsupported statement with a cloud AI model, redact your name, street address, account numbers, and Social Security / Tax ID numbers using a PDF editor or by blacking out personal identifiers. The AI agent only needs to understand the table headers, line-item column order, and numerical delimiters to write an accurate parser.
  • Use Local Offline LLMs When Feasible: You can point your coding agent to an offline local model (via Ollama or LM Studio) to inspect the statement and write the parser entirely on your local machine with zero external network transmission.
  • Share Generic Parsers Upstream: When submitting your parser script to the repository, ensure the script contains only generalized parsing logic and regex pattern matching, with no hardcoded personal account numbers or personal transaction data.
