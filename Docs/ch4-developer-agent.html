Chapter 4 Developer & MCP

Developer & Agent Integration

Model Context Protocol (MCP) server, external tool calls, threat modeling, and prompt injection defense.

4.1 External Agent MCP Integration

AdvisorBot includes a high-performance Model Context Protocol (MCP) server (Scripts/mcp_server.py). This enables AI agents in Claude Desktop, Cursor, or Gemini CLI to safely interact with your portfolio using the Python interpreter inside your virtual environment (.venv):

Platform Commands:
macOS ~/Library/Application Support/Claude/claude_desktop_config.json 
{
  "mcpServers": {
    "holdings-tools": {
      "command": "/absolute/path/to/AdvisorBot/.venv/bin/python",
      "args": ["/absolute/path/to/AdvisorBot/Scripts/mcp_server.py"]
    }
  }
}
Linux ~/.config/Claude/claude_desktop_config.json (or .cursor/mcp.json) 
{
  "mcpServers": {
    "holdings-tools": {
      "command": "/absolute/path/to/AdvisorBot/.venv/bin/python",
      "args": ["/absolute/path/to/AdvisorBot/Scripts/mcp_server.py"]
    }
  }
}
Windows %APPDATA%\Claude\claude_desktop_config.json 
{
  "mcpServers": {
    "holdings-tools": {
      "command": "C:\\path\\to\\AdvisorBot\\.venv\\Scripts\\python.exe",
      "args": ["C:\\path\\to\\AdvisorBot\\Scripts\\mcp_server.py"]
    }
  }
}
Remember to escape backslashes (\\) in Windows JSON paths. Cursor (.cursor\mcp.json) and Gemini CLI (%USERPROFILE%\.gemini\settings.json) use the same mcpServers schema.

The MCP server (holdings-tools) honors the active Privacy Shield mode (automatically upgrading to identity_and_values scaled by demo_mode.scale_factor whenever Demo Mode is enabled, even if ai_shield.mode is off) and exposes seven tools over local stdio IPC: read/analysis tools (holdings__get_overview, holdings__query_positions, holdings__run_simulation, holdings__compute_non_primary_growth, and holdings__solve_simulation) plus stateful scenario and browser tools (holdings__manage_saves for creating, loading, renaming, deleting, and upvoting scenarios, and holdings__control_live_ui). Protected scenarios reject overwrites/deletions unless overwrite_existing=True and confirmed_by_user=True are explicitly passed (and Demo Mode blocks all scenario/UI mutations).

4.2 MCP Security & Prompt Injection Defense

While the MCP protocol allows desktop agents to provide deep insights on your wealth, exposing personal financial data to LLM agents requires careful attention to the threat model:

Transport Isolation & Zero Network Surface

AdvisorBot's MCP server communicates strictly over local stdio IPC (standard input / standard output). It opens no listening network ports, accepts no HTTP connections, and cannot be accessed from web browsers or LAN devices. Furthermore, the server contains zero network egress tools—it cannot send outbound HTTP requests or exfiltrate data on its own.

Understanding the Indirect Prompt Injection Risk

The security risk with MCP does not originate in the MCP server itself; it arises from the capabilities of the host CLI agent running in your terminal:

The Dual-Tool Threat Vector: If an external agent (e.g. Claude Code or Gemini CLI) has access to both:
  1. AdvisorBot's MCP Tools (which read sensitive portfolio balances, accounts, and holdings), and
  2. General-purpose execution tools (like curl, bash, or web search/browsing),
an attacker could embed an indirect prompt injection in an untrusted document (PDF, webpage, or email) that you ask the agent to inspect. The injection could trick the LLM into treating hidden text as system instructions, prompting it to call holdings__get_overview and exfiltrate your financial records to an external server via curl.

Best Practices & In-App Management

  • Master Privacy Toggle & Shield Enforcement: Under Settings > Privacy, the Model Context Protocol (MCP) row allows you to enable or disable the service with a single click. When disabled or when privacy configuration fails to parse (fail-closed), the server strictly blocks all tool invocations. When MCP is enabled, identity_aliased aliases identities and identity_and_values also scales values (and enabling Demo Mode upgrades even off / identity_aliased to identity_and_values scaled by demo_mode.scale_factor). off permits clear results in Live View, while local_only blocks MCP calls. Overwriting or deleting protected scenarios requires both overwrite_existing=True and confirmed_by_user=True.
  • Decoupled Runtime: The in-app web dashboard and built-in AI Chat do not use MCP. You can keep the MCP server Disabled full-time without losing any browser features.
  • Context Isolation: Never instruct a CLI agent that has access to financial MCP tools to read untrusted third-party web content or untrusted attachments within the same conversation session.
  • Sandboxed Agents: Configure financial agents in desktop containers (e.g. Claude Desktop) that do not have unrestricted terminal/bash access or arbitrary outbound networking.

4.3 Security, Privacy & Portability Engineering Guardrails

Contributors modifying server, LLM, ingest, simulator, or UI templates must uphold these non-negotiable invariants:

  • Fail-Closed Privacy Shield & Leak Check: Cloud LLM requests and MCP tools must always resolve the active Privacy Shield (defaulting to blocked on config read errors) and validate scrubbed payloads via _assert_wire_leak_free() before transmission. In Mode C (identity_and_values), scale every numeric field unless its key is explicitly allowlisted as non-monetary.
  • Credential Hygiene & Dynamic Aliasing: Pass Gemini API keys strictly via the x-goog-api-key HTTP header (never URL query strings), never place secrets into CLI flags or shell commands, and enforce 0o600 permissions / 0o077 umask on tokens, configs, SQLite DBs, badges, snapshots, and privacy_registry.json (real account/contract IDs display in Live View and are dynamically aliased in Demo Mode and Privacy Shield Modes B/C).
  • Safe Subprocesses & Auth Gates: Never invoke CLI agents with --dangerously-skip-permissions or shell=True; pass untrusted prompts via stdin with --disable-slash-commands. Bind ThreadingHTTPServer to 127.0.0.1 before writing Data/.session_token and gate all API routes behind host + token validation.
  • Parser, XSS & Portability Hardening: Use defused/bounded XML/XLSX/PDF limits, reject symlink escapes outside the workspace, escape dynamic HTML with escHtml(), never hardcode household-specific tickers, dates, or dollar fallbacks in Scripts/, and keep Python (simulator.py) and browser JS (app_simulator.js) simulation engines in 1:1 parity.

4.4 Isolated Test Suite & Verification

Every test under Scripts/tests/ runs strictly against six synthetic fixture portfolios (p0_empty_household, p1_index_saver, p2_equity_comp_rsu, p3_retiree_annuities, p4_trust_household, and p5_adversarial) inside ephemeral scratch directories. Autouse runtime guards in conftest.py refuse to run against non-fixture roots and block outbound non-loopback network calls, guaranteeing that running tests never touches your real Portfolios/ directory.

Tier Scope & Verification Coverage
unit Pure functions: progressive tax models, 7-class risk taxonomy, Privacy Shield translator, and fixture determinism.
parsers Institution statement parsers against golden page text plus canonical *.statement.json and *.grants.json plugins.
pipeline Statement ingestion → SQLite persistence → forecast enrichment → view-model assembly on synthetic fixture roots.
engine 40-year / 100-year solvency simulator, goal-seek bisection solver, Monte Carlo bands, and 1929–2025 historical cohorts.
parity 1:1 milestone, tax, optimizer, Monte Carlo, and cohort equality between Python (simulator.py) and browser JS via Node VM.
server advisorbot_server.py loopback Host/Port guards, session cookie bootstrap, CSRF checks, Demo Mode projection, and protected scenario locks.
llm Privacy Shield Modes A/B/C, bidirectional alias round-trips, and outbound wire-leak gates against a fake provider.
render & scans Template JS syntax checks, dirty-state tracking, zero-PII/home-path hygiene, zero literal fallbacks, and portability denylist checks.

Install the optional test extra (pip install -e ".[dev]") and run the suite from the repository root:

macOS Terminal (zsh / bash) 
# Full default suite (~2 min) or a single tier / security subset
make test PYTHON=.venv/bin/python
make test-tier T=server PYTHON=.venv/bin/python
make test-security PYTHON=.venv/bin/python

# Verify fixture determinism, parser golden fixtures & hygiene scans, or dry-run a plugin
make fixtures-check PYTHON=.venv/bin/python
.venv/bin/python -m pytest -q Scripts/tests/parsers Scripts/tests/scans
.venv/bin/python Scripts/holdings.py inspect-statement path/to/statement.pdf
.venv/bin/python Scripts/holdings.py test-plugin path/to/statement.pdf --offline
